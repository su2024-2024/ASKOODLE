Transcribe's standard batch API is simpler to integrate but adds several seconds of lag per question — avoid it for this use case.

Why 80% is a defensible number

board Q&A · how to justify the rules-first split

1. Look at what students actually do on a typical school day

In a K-12 learning app for Grades 6–12 India curriculum, the majority of student interactions are structured activities, not open questions:

Student actionType% of interactions
Practice MCQs from chapter exercisesRules~40%
Check “is my answer right?” on worksheetRules~20%
Revisit concept flashcards / definitionsRules~10%
Ask “why is this wrong?” or “explain this”AI~20%
Ask a free-text doubt in own wordsAI~10%

This is not a guess — this is the pattern from existing EdTech platforms (BYJU’S, Khan Academy, Embibe all report 60–75% of interactions are structured practice, not open queries).

2. The curriculum itself is the proof

India NCERT syllabus for Grades 6–12 is mostly closed-answer content:

  • Mathematics: every problem has one correct answer
  • Science MCQs, fill-in-the-blank, numerical problems — all rules
  • History/Geography: factual recall questions — rules
  • Only “explain in your own words” essay-type questions need AI

80% of the question types in the textbook are closed-answer — you can literally count them chapter by chapter.

3. How to say it to the board

“We did not assume 80%. We counted. We took 3 chapters from NCERT Grade 8 Maths and Science and classified every exercise question: MCQ, fill-in-the-blank, numerical, true/false — these are all rules-based. Only the ‘explain’ and ‘describe’ questions need AI. The ratio came out at 78% rules, 22% AI. We rounded to 80/20. Our Discovery Stage will validate this against real student interactions in 5 schools.”

4. What if the board pushes back — “what if students ask more free-text?”

“Then our cost goes up from ₹0.25 to ₹0.40 per answer — still well below our ₹1 guardrail. The 80/20 split is our cost floor, not a ceiling. If students ask more open questions, that is actually a signal of higher engagement — which is what schools are paying for.”

One-liner for the slide

“80% is not an estimate — it is the shape of the NCERT curriculum. Closed-answer questions are rules by definition.”
Before you present: the “78% / 22%” split was not measured yet, and the 60–75% EdTech figures need a source check. Only say “we counted” after the chapter count is done. Otherwise label both as estimates to validate in Discovery.

Demo and production are intentionally different

what runs today vs. what ships

The demo optimizes for zero or minimal provider cost. Production optimizes for predictable quality, text-bearing educational visuals, document grounding and measurable validation — with every AI model called by API, no self-hosted GPU inference to operate.

CURRENT DEMO

Free / low-cost provider chain

  • Flask + Jinja2 + SQLAlchemy application
  • DeepSeek → Gemini 1.5 Flash → Groq → local FLAN-T5 fallback for text — DeepSeek/Gemini keys are not currently set; live demo traffic runs entirely on the Groq step (Llama 3.3 70B, free tier)
  • BAAI/bge-small-en-v1.5 + LlamaIndex hybrid vector/keyword retrieval
  • Cloudflare FLUX.1 Schnell → Pollinations → RunPod image fallback
  • S3 image cache, Razorpay checkout, AWS/Cloudflare delivery
  • Voice-to-text: Groq-hosted Whisper large-v3-turbo API (mic button, free tier, same key pool as text)
  • Text-to-voice: macOS say command + ffmpeg — on-device narration, cached to MP3 by content hash, zero cost, macOS-only (won't run on Linux hosting)
  • Explicit unlimited teacher/student demo accounts for frictionless demonstrations

Purpose: product demonstration and workflow validation. These free-provider costs are not used in the production margin table.

APPROVED PRODUCTION

Governed education AI stack

  • Gemini Embedding 2 for OCR + production embeddings
  • OpenAI text-embedding-3-small API for embeddings fallback — cheapest option, no self-hosting
  • DeepSeek V4 Flash for user-facing answer generation; Qwen 3.6 Flash for independent answer verification — a genuinely different provider from the generator, at a comparable cheap-tier price, no self-hosting
  • GPT Image 2 Low primary; Qwen-Image-2512 fallback via Replicate/WaveSpeed API — cheapest at $0.02/image, no self-hosting
  • Voice-to-text: Amazon Transcribe Streaming replaces Groq Whisper — same AWS account as storage/Polly, but needs a real client-side rewrite (WebSocket audio streaming) to keep today's instant response feel; $0.024/min base tier, 15s minimum per request
  • Text-to-voice: Amazon Polly (Neural) replaces the macOS-only say engine, which cannot run on Linux hosting — $16/1M characters, same AWS account
  • Policy gates, audit and tenant isolation
  • Application tier hosted on AWS (EC2/RDS/S3/CloudFront) — see AWS Hosting Cost tab

Purpose: commercial delivery using the model and control layers shown in the Architecture tab. Launch stack is API-only for every AI model; self-hosted GPU inference is a later scale option, not a launch requirement.

Configuration issue to close before production: the demo provider chain still defaults to legacy aliases such as deepseek-chat and gemini-1.5-flash. The paid environment must set and test explicit production model identifiers rather than relying on demo defaults.

Verification Metrics — How We Know the Checker Works

Each number measured against teachers' own labels on a 200-question gold set

The verification gate (FR4) is only as trustworthy as its measured performance. These five metrics are tested on a 200-question gold set where teachers have already labelled every claim as correct or incorrect. Each metric has a hard threshold — below it, we act, not discuss.

≥95%

Passed facts teachers confirm

Of all the facts the AI judge passed as correct, at least 95% must actually be correct when teachers check them independently. This is the system's precision — how much you can trust a "Verified" badge.

→ Below 90%: pivot to teacher copilot (stop student-facing AI answers entirely)
<2%

Bad calls: wrong shown as verified

The most dangerous failure — a wrong answer displayed with a "Verified" badge. The student trusts it, the teacher doesn't see it. This is the false-positive rate of the verification gate and must stay under 2%.

→ Above 2%: pause the pilot immediately
κ ≥0.70

Judge–teacher agreement (Cohen's kappa)

Cohen's kappa measures how much the AI judge and human teachers agree beyond chance. A κ of 0.70 means "substantial agreement" — the AI judge and teachers disagree only on genuinely ambiguous claims, not on clear facts.

→ Below 0.70: re-tune the 0.8 confidence cut-off in the policy gate
≤2%

Escalation rate (sent to a human)

The share of all answers that the policy gate escalates to a human SME for review. At launch, ≤2% is acceptable. Before scaling to more schools, this must drop to ≤0.7% — otherwise the human review queue becomes a bottleneck.

→ Above 0.7% at scale: do not expand to more schools
<4 s

Latency (95th percentile)

95 out of every 100 verified answers must reach the student in under 4 seconds — including retrieval, generation, claim extraction, evidence matching, and the judge verdict. On low-bandwidth Android, anything slower breaks the learning flow.

→ Slower: fix before release (optimize retrieval, reduce prompt size, or cache)
Why these five and not more? Each metric maps to a specific actor's trust: ≥95% and <2% protect the student (correct answers, no false "Verified" badges); κ ≥0.70 proves to the school board that the AI judge is as reliable as a teacher; ≤2% escalation shows operations the system doesn't drown the SME queue; and <4 s latency tells product the experience isn't broken. Together they form the go/no-go checklist before every scale decision.
